# Frozen receiving comparison

A confirmed positive carton count equal to the purchase order supports full receipt. A confirmed positive lower count supports partial receipt. Hold a zero, an overage, a missing physical count, a unit mismatch, or unresolved disagreement. A clearly superseded count is historical. Independent non-overlapping stacks may be added. A declared shipment or driver estimate is distinct from a physical count.

Use the same twelve supplied notes with the same extraction prompt on each real Firebase path. Record actual inference source, model identifier when provided, raw extraction, validation, and elapsed time. Use the uncorrected extraction for scoring. The app may separately allow operator edits. Keep the expected labels out of prompts, support calculations and model inputs. Record malformed extractions and service errors explicitly. Give the baseline and hosted selector identical case evidence and candidate menus, including any locally computed support. Disclose the effect of those support values. Measure incorrect acceptance, correct holds, unnecessary holds, exact decision matches, device/cloud disagreement and latency. Keep failures in the denominator. Never interpret request failure as a valid refusal. Use at most one hosted evaluation per case per inference path, or 24 total. Store a sanitized receipt or failure outcome for each call.
